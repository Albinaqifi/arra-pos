## What a waiter can finish

Reopening the bill reads local records. The waiter can choose **Finish recording payment** when Arra already has the verified closed document acknowledgement. For a newly journaled Cash A sale on the enrolled on-site firmware, the same action is available if the app lost the final result but saved every validated reply through the final document number. The check compares the original bill and device, every item request, the cash tender, close counters and document number. It requires the complete command sequence. Bill review leaves the database untouched.

Finishing uses the original document number. Arra records one Cash A payment under the saved payer and audits the waiter who finishes it. It can finish after restarting without the printer profile. The action never sends a printer command or dispatches a Windows slip. Existing order ownership still applies. Synthetic history exercises distinct payer and finisher IDs. Current waiter entry has no cross-waiter handoff for an occupied order.

An acknowledged command to open, tender or close alone is insufficient. A lost reply, mismatching bill, partial trace or unjournaled historical attempt without a verified result stays unresolved. A prepared checkout in the current database can be released before dispatch. An older backup can predate a sale that the printer has already recorded. A missing command in that backup cannot establish that the sale never started.

The operator reconciled the original espresso incident. An earlier read of a reconciled closed document found the supplied item phrase. The owner also completed two hands-on training recoveries on the POS PC using the simulated printer.

The v5 USB diagnostic compares complete item, total and Cyrillic cash lines locally with the paper from a reconciled last receipt. It reports counts, the end marker and occurrences of the document number. It never accesses Arra's database. Its inquiries can overwrite the printer's last command reply. Keep it closed if any sale or fiscal report is unresolved or the last document cannot be identified.

On the POS PC the owner confirmed the last receipt was completed and recorded in Arra, with the business day still open. The v5 read returned 32 text lines and stopped at the document separator. The complete total line matched once, the complete Cyrillic cash line matched once and the separate document-number token appeared on one line. The complete item line matched zero times. The number-token count does not identify its field. The summary retains no item text from the journal. This read used the already closed receipt and issued no print or sale command.
