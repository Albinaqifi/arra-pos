# S-003 — Connect screens to local application services

**State:** In progress; acceptance, independent review and testing passed; awaiting PR and merge. Base: `d42f9d5` (S-002 merge).

The desktop screen obtains development application information through a sandboxed preload exposing one method. The main process validates the sender, frame and empty request; the preload validates the response and returns a safe error. The browser demo remains available without the bridge. No order persistence is introduced.

**Builder checks:** `npm test` passed 7 tests; `node --check` passed for the desktop main, preload and status scripts; `git diff --check` passed.

**Review:** Independent reviewer approved the complete tracked and untracked change with no actionable findings.

**Tester:** Independently ran `npm test`: 7/7 passed (Node emitted the SQLite experimental warning). A sandboxed Electron launch failed before startup with exit `0x80000003`. An isolated Electron launch outside the sandbox, using a disposable wrapper and user-data directory, blocked HTTP and HTTPS requests and loaded the actual desktop app. It displayed `Arra POS · development`, exposed only `getApplicationInfo`, returned the expected response, and had no renderer `require` or `process`; exit 0. This simulates blocked network requests, not a physically disconnected adapter.

**Outstanding:** PR and merge; no production use. The desktop UI is still a demo, and persistent tables and orders are later stories.
