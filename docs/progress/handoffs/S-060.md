# S-060 — Protected shared administration

**State:** In progress; independent review approved and focused testing passed; PR pending. Base: `9af9306`.

**Changes:** Version 28 grants existing owner scopes shared configuration; version 29 records pending staff until Combined establishes a password. Owners can configure menu and tables and manage staff account details. Only Combined may create usable staff credentials, reset passwords/PINs, change operational grants, or manage owner accounts and financial access. A/B can create inactive pending staff records with an undisclosed random password for Combined to provision. Pending records cannot be activated or selected until Combined sets a password, including after restart. Legacy waiter administrators cannot grant permissions or reset/create usable credentials. Owner selection of a PIN-less waiter does not authorize waiter operations. Changes are attributed; menu destination changes are included in audit snapshots. Financial scope changes invalidate the target session. A usable Combined must remain active if a Combined scope exists. The first account created on an empty database is Combined; Combined can provision a separate waiter.

**Legacy sample setup:** The owner approved an isolated setup for old test databases. The helper requires an existing `SAMPLE-DATA-ONLY` marker, an authenticated active waiter administrator with both employee grants, and no owner or unscoped accounts. It creates an audited Combined setup on a new copy, preserves the source, and removes failed copies. Unmarked legacy databases are unsupported. README documents the command and scope. No user database was modified or used in verification.
