## Restaurant RC5 desktop release

Based on the restaurant RC4 launcher at `ac1f618`. RC5 carries the owner-approved faster four-digit waiter credential format. Existing waiter PINs continue to work. Combined can reset each active waiter to the same digits for the full speed improvement. New and reset waiter PINs are readable by someone with access to the database or a decrypted backup. Combined and transfer PINs and account passwords remain salted and hashed. Promoting a waiter rehashes their direct credential in the same transaction. RC4 cannot verify direct waiter PINs. Keep using RC5 with the current restaurant database after resets.

The package builder verifies the original RC4 ZIP and overlays the four PIN-related desktop modules. For the RC4-specific setup script it applies only the credential changes. It bundles a Windows GUI launcher with file version `1.0.10.5`, the verified program and a staff guide. Rebuild with `python scripts/desktop-launcher/build.py --rc5 <verified-RC4.zip> <new-RC5.zip>`.

The release-branch build and 920/920 tests passed. After the final promotion change, `node --test tests/waiter-pin-uniqueness.test.js tests/owner-approval.test.js` passed 6/6 and `node --test tests/waiter-pin-fast-transition.test.js` passed 1/1, including failed-promotion rollback, repair of a malformed credential and reservation of a former waiter PIN.

- A fresh source reviewer approved the final changes after correcting the guide. Opening RC4 after a single active waiter PIN is converted can block table entry for every waiter. The reviewer independently matched all 183 runtime files to the manifest embedded in the RC5 launcher.
- The package tester seeded a restaurant with five synthetic waiters and an occupied table using the actual RC4 modules. Against the RC5 ZIP, all five original PINs worked. Only Combined could reset them. Mixed credentials and table ownership survived restart and encrypted backup restore into a separate directory. Median trusted PIN lookup across 15 attempts fell from 876 ms to 2.86 ms after all five same-digit resets on the test PC.
- The packaged checkout rehearsal verified one fiscal bill each for Cash A and Card A on a simulated PF700, one itemized Cash B bill on the Bar queue, and no duplicate payment or output after retry and restart. The private Windows GUI rehearsal generated a desktop shortcut and protected printer profile with the genuine RC4 launcher and opened RC5 from that same target. The shortcut and settings stayed byte-identical, and startup created no payments or print attempts.

The package checks used disposable local scripts under `build/rc5-rehearsal` (`pin-upgrade.cjs`, `payments.cjs`, and `gui.ps1`). Installation on the restaurant PC, real paper output and waiter timing on that PC remain unverified.
