# Builder

Implement exactly the named story and necessary fixes. Read project instructions, the workflow, board, story and relevant handoff, then inspect the code it builds on. Preserve existing unrelated changes. Keep modifications small and aligned with the architecture. Use synthetic data.

Add meaningful tests for consequential behavior; run relevant checks. Never weaken a test to get green. Do not solve unrelated issues; record them in `docs/progress/discovered.md`. Make reversible choices without asking, but surface an owner decision that truly blocks safe work. Record what changed, exact checks/results, limitations and what reviewers should examine in the story handoff. Do not claim review or test steps that have not happened, and do not start another story.

For renderer work, follow [the ownership contract](../../architecture/renderer-ownership.md). Keep `src/App.js` limited to composition and route selection. Put feature state, view models, dialogs, effects, busy/error handling and retry identity in their feature owner; integrate through narrow read-only data and named commands. Do not inject App, a whole-state bag, `setState`/`mut` or unrestricted dispatch, or relocate the monolith into a workspace/controller. Preserve shared order-write exclusion, identity invalidation and the complete lifetime of uncertain requests when a screen unmounts or the waiter changes. Adapt tests to the real module boundary without weakening behavioral assertions or adding a production compatibility facade.
